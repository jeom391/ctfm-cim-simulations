## 2. 사용 데이터와 적용 수식

| 항목 | 사용 파일 |
|---|---|
| C2C | `data/team-snapshot/2026-10-02/files/C2C/A2_C2C_50Cycles.xlsx` |
| D2D | A1 `vgid_sweep_200/201`, A2 `IdVg_sweep_233/234`, A3 `vgid_sweep_245/246`, A4 `IdVg_sweep_232/233`, A5 `IdVg_sweep_223/224` (각 `_15V`) |
| LTP/LTD | A1 `A1_LTP/LTD.csv`, A2 `A2_LTP/LTD.csv`, A3 `LTP/LTD_512_A3_228.csv`, A4 `…A4_229.csv`, A5 `…A5_234.csv` |
| Retention | `_26CMFM_A1~A5_Retention.xlsx` (`Raw Data`, t ≥ 10 s) |

```text
C2C 전체 변동      CV = 100·SD(I, N−1) / |mean(I)|
C2C 추세 제거      T_n = a + b·n (n=1..50, OLS) ; e_n = (I_n − T_n)/T_n ; CV = 100·SD(e, N−1)
                   (회귀 잔차 SD sqrt(Σr²/(N−2))/mean 과 다른 정의 — 3.083/2.507 % 와 혼용하지 않음)
D2D 조건 k         G = Id(Vg=0)/0.1 V ; CV_k = |G1−G2|/√2 / mean(G1,G2)
D2D 대표값         CV_D2D = sqrt(Σ CV_k² / K)       (조건 = 진폭 × {erase=상승, program=상승 직후 하강})
LTP/LTD 상태       상태 전류 = 쓰기 펄스 직전 읽기 샘플(전이 2행 전, VGS≈0 V) ; G = I / 0.1 V
가중치 매핑        scale = max|w| / (Gmax−Gmin) ; G± = 측정 상태 중 (Gmin + |w|/scale)에 가장 가까운 값 ; w' = scale·(G+ − G−)
시뮬레이터 적용    c = CV/100 ; τ = sqrt(log1p c²) ; F = exp(−τ²/2 + τ·Z) ; 두 전도도 plane에 곱함 (D2D=배열별 고정, C2C=재기록별)
Retention          I(t) = a + b·log10(t/1 s), 실측 구간 OLS → 10년(3.15576e8 s)까지 외삽(모델 결과, 0 이하는 자르지 않음)
```

## 4. 실제 AIHWKit 실행 (같은 프로필 A2, 같은 가중치, ADC 5 bit, 64×64, seed 20260917)

공통: 디지털(FP32) D0 96.46 %, 입력 8 bit D1 96.48 %, 매핑 후 M0 96.47 %. 6개 실행의 checkpoint 가중치는 파일 해시는 다르지만(메타데이터) `torch.equal`이 모든 텐서에서 True.

| 실행 | 입력 | 재기록/배열 | 효과 적용 후 정확도 (각 실행) | 평균 | 주입 배율의 경험 CV |
|---|---|---|---|---:|---:|
| C2C OFF | — | 1 | 95.64 | 95.64 % | — |
| C2C 추세 제거 후 | 2.9179 % | 5 | 95.67 / 95.51 / 95.66 / 95.73 / 95.83 | 95.68 % | 0.0291 |
| C2C 전체 변동 | 6.0755 % | 5 | 95.57 / 95.72 / 95.55 / 95.78 / 95.61 | 95.65 % | 0.0605 |
| **검증용** C2C 30 % | 30 % (연구 승인값 아님) | 5 | 92.98 / 91.62 / 93.27 / 93.33 / 92.73 | 92.79 % | 0.2987 |
| D2D | 47.3534 % | 배열 3 | 82.63 / 90.34 / 81.98 | 84.98 % | (배열별 고정) |

그림: `fig1_accuracy_by_condition.png`

해석(과장 없이):
- 입력값 전달: `effective_config.candidates[].c2c.cv_percent`가 6.0755 / 2.9179 / 30, C2C OFF 실행에는 없음. 실제 주입된 배율의 경험 CV가 입력과 일치(0.0605, 0.0291, 0.2987). 입력값이 계산에 전달된다는 증거는 이 기록과 30 % 검증 실행(정확도 −2.9 %p)이다.
- **2.9179 %, 6.0755 %, OFF 사이의 정확도 차이(≤ 0.04 %p)는 재기록 5회의 변동폭(±0.1~0.15 %p)보다 작아 구분되지 않는다.** 이 조건에서는 두 C2C 추정치 선택이 정확도에 유의한 차이를 만든다고 말할 수 없다.
- "대표 스윕 구간이 미확정"이므로 §3.1의 수치로 만든 2.9179 / 6.0755는 **검증용 입력**이며 연구적으로 승인된 대표값이 아니다. 30 %는 입력 전달 확인용이다.
- D2D 배열 난수는 프로필 해시(프로필 UUID 포함)로 정해진다. 같은 파일을 다시 올리면 새 프로필이므로 배열 추첨이 달라진다(개발자 보고 86.37 %는 82.17–89.20 범위, 이번 84.98 %는 같은 범위). 설계상 동작이며 이번 변경 범위가 아니다.
- 6장 카드 한 번의 실행(ADC만): A2 96.47→95.64, A1 96.43→95.89, A3 96.47→94.48, A4 96.48→94.56, A5 96.45→88.41, 여섯 번째 카드(A1 파일 업로드 후 A4 파일로 교체) 96.48→94.56. A1·A3·A4·A5는 개발자 보고와 동일. 교체한 카드가 A4와 정확히 같은 값이 나온 것이 교체 반영의 증거.

## 7. 확인 방식 구분

- **직접 확인(독립 계산·실행·화면)**: §1~5의 전 항목.
- **자동 테스트로만 확인**: 결측·음수·평균 0·비양수 추세(C2C), Retention 외삽 overflow 경계, 다운로드 이스케이프 일부. 백엔드 `500 passed, 12 skipped`(skip은 개인 폴더·원본 A1/A3 C2C 파일 부재 사유, 이전과 동일), 웹 `58 passed`.
- **확인 필요(직접 수행 불가)**: 운영체제 **파일 선택창을 열어 선택하는 클릭 경로**. 내장 브라우저 도구는 네이티브 대화상자를 조작할 수 없고 Claude in Chrome은 이 세션에 연결된 브라우저가 없다. 그래서 이번 브라우저 검증은 페이지 안에서 원본 파일을 읽어 `File` 객체를 만들고 파일 입력에 넣은 뒤 `change` 이벤트를 발생시키는 방식(앱의 업로드·분석·저장 코드는 그대로 사용, 네이티브 대화상자만 우회)이다. 필요하면 서버를 띄운 뒤 `파일 선택`을 한 번만 눌러 A2 LTP/LTD 두 파일을 고르는 확인 1회가 남는다.
- **연구·소자팀 결정(구현 미완료 아님)**: 상승/하강 중 대표 구간, 측정 VDS 0.1 V 여부, D2D 파일번호↔물리 소자 대응, 로그정규 가정의 적합성. 이번 수치는 모두 검증용이다.

## 8. 참고 관찰 (결함 아님)

- 분석 PNG의 제목·범례는 영어(한글 글꼴 없음). 화면 문구·CSV는 한국어.
- 저장 후 폐기한 임시 결과의 artifact 디렉터리는 의도적으로 남는다(`cleanup`이 checkpoint를 지우지 않도록 설계됨).
- M0 정확도: 이 환경 AIHWKit(float32)는 A2에서 96.47 %, 개발자 환경은 96.46 %로 1장 차이. 효과 적용 후 값(95.64 %)과 A1·A3·A4·A5 값은 동일하게 재현됨.
- `serve.sh`는 기본값이 `/opt/ctfm-engines`다. 이 PC처럼 엔진 폴더가 다르면 `CTFM_ENGINE_ROOT`, `CTFM_SERVE_ROOT`를 지정한다.

## 9. 실행·종료

```bash
# 최초 1회: 웹 번들 (WSL)
cd apps/web && npm run build

# 실행 (WSL, 엔진 폴더가 /opt/ctfm-engines 가 아니면 환경변수 지정)
CTFM_ENGINE_ROOT=$HOME/ctfm-engines CTFM_SERVE_ROOT=$HOME/ctfm-engines/serve PORT=8000 bash scripts/linux/serve.sh start
bash scripts/linux/serve.sh status
# 브라우저: http://127.0.0.1:8000

# 종료 (저장 결과는 유지)
CTFM_ENGINE_ROOT=$HOME/ctfm-engines CTFM_SERVE_ROOT=$HOME/ctfm-engines/serve bash scripts/linux/serve.sh stop
```

테스트: 웹 `cd apps/web && npm test && npm run build`, 백엔드는 엔진 환경에서 `pytest`.
