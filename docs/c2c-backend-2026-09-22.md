# C2C API/worker/결과 연결 (웹 제외) — 2026-09-22

[C2C 계산 모듈](c2c-core-module-2026-09-22.md)을 API 요청 → worker 실행 → 결과/export까지 연결했다. 상세 근거·검증은 `local_report/04_REPORT_c2c-backend.md`를 참고한다. **웹 입력 화면은 이번 범위 밖이다.**

## 버전과 호환 정책

- 요청/결과 schema는 `1.2.0`과 `1.3.0`을 모두 받는다(`packages/contracts/schemas/experiment-request.schema.json`의 `schema_version` enum). **1.2.0 요청은 원래 의미를 완전히 보존한다** — `effects.c2c`는 여전히 `const:false`, `n_reprogram`은 여전히 `const:1`로 강제되며(스키마의 `schema_version`-조건부 `allOf` 항목), 기존 1.2 fixture/테스트는 무수정으로 계속 통과한다.
- `1.3.0`만 `effects.c2c=true`와 `n_reprogram` 1~100을 허용한다. `packages/ctfm-core/src/ctfm/simulation/__init__.py`의 `_validate()`도 동일하게 이중 검사한다(스키마를 우회해 `run_experiment()`를 직접 호출하는 테스트/스크립트도 안전하도록).
- 기존 저장된 1.2 결과나 profile은 마이그레이션하거나 덮어쓰지 않았다. `/capabilities`의 `schema_version`은 `"1.3.0"`(현재 권장 버전)을 보고하지만 `1.2.0` 요청은 그대로 계속 동작한다.

## 요청 계약(1.3.0 추가분)

`profile_refs[i].c2c`(1.3.0 + `effects.c2c=true`일 때만 각 항목에 **필수**):
```json
{"cv_percent": 5, "source": "manual_assumption"}
```
- `cv_percent`: JSON Schema `type:number`(불리언 자동 배제) + `minimum:0`. `_validate()`에서도 Python `isinstance(...,bool)`을 별도로 거부한다(JSON 경계를 우회하는 직접 호출 대비).
- `source`: 반드시 `"manual_assumption"`. 다른 값이나 누락은 거부.
- **암묵 복사 없음**: 요청에 프로필이 여러 개면 각 항목이 자신의 `c2c`를 명시해야 한다. 하나만 채우고 나머지를 비우면 스키마 단계에서 거부된다.
- `effects.c2c=false`이면 어떤 `profile_refs[i]`도 `c2c` 키를 가질 수 없다(값이 유효한 객체여도 거부 — "미리 채워진 것처럼 보이지 않게").
- `n_reprogram`: 정수 1~100. `effects.c2c=false`이면 반드시 1.
- 실행 수 예산(`MAX_REQUESTED_RUNS=2000`)에 `n_reprogram`을 곱한다: `profiles × pools × mappings × arrays × n_reprogram × years`.

## 실행 의미 (packages/ctfm-core/src/ctfm/simulation/__init__.py)

- `G_program = G_nominal × D2D_factor × C2C_factor`, 그 다음 Retention 비율 적용(기존 순서 유지).
- D2D는 배열마다 1회 고정(기존과 동일). C2C는 **(array_index, reprogram_index, layer, polarity)**마다 독립적으로 새로 뽑는다 — `ctfm.simulation.math.c2c_factors`의 RNG 키에 `adc_order`/`years`는 없으므로, 같은 (array, reprogram) 조합은 ADC 순서를 바꾸거나 시간(retention year)을 바꿔도 항상 같은 표본을 재사용한다(순수 함수, 별도 캐시 불필요).
- `effects.c2c=false`(기존 동작)일 때 `record_layers`는 `array_layers`를 그대로 참조한다 — 사본을 만들지 않고 새 계산 경로도 타지 않으므로, off 결과는 이번 변경 이전과 **완전히 동일**하다(관련 기존 테스트 34개 무수정 통과로 확인).
- `run_id`: `candidate_id-array-{array}-year-{year}`(기존, `n_reprogram=1`일 때 그대로) 또는 `candidate_id-array-{array}-record-{reprogram}-year-{year}`(`n_reprogram>1`일 때만). 각 ALL run에 `reprogram_index` 필드를 항상 명시(기존 `array_index`와 동일한 위상).
- D0/D1/M0는 재기록 축과 무관하게 후보당 정확히 1회만 계산(기존과 동일, 변경 없음) — 재기록 때문에 재학습/재매핑하지 않는다.
- **통계 구분**: `summary.array_statistics[i].accuracy`는 배열마다 "그 배열의 재기록 평균" 1개 값만 넣어 요약한다 — 동일 배열의 여러 기록을 독립 배열로 세지 않는다. `n_reprogram>1`일 때만 `reprogram_accuracy_by_array`(배열별 재기록 분포)를 추가로 채운다. `n_reprogram==1`(off)이면 이 필드는 `None`이고 `accuracy`의 수치는 기존과 완전히 동일하다.
- C2C 진단(`c2c_diagnostics`, ALL run에 포함): 각 layer/plane마다 `seed`, `factor_mean`, `factor_std`, `factor_empirical_cv`(**factor 자체**에 대해서만 계산 — G_program에 대해 계산하지 않음, `ctfm.simulation.math.c2c_factor_statistics`의 문서화된 이유와 동일), `outside_observed_fraction`/`min_s`/`max_s`(`observed_range_violation`, 자동 clipping 없음).
- 산출물: `{candidate}-array-{array}-record-{reprogram}.json`(`effects.c2c=true`일 때만 저장) — seed 목록 + 위 진단 + `cv_percent`/`cv_ratio`/`source`. **원시 factor 배열(npz)은 저장하지 않는다** — D2D와 달리 재기록 축이 최대 100배까지 커질 수 있어 원시 배열을 매번 저장하면 산출물이 과도하게 커진다. `c2c_factors`가 seed로부터 완전히 재현 가능한 순수 함수이므로 seed+통계만으로 재현·검증할 수 있다는 것이 근거다.

## `/capabilities` 변경

- `schema_version`: `"1.2.0"` → `"1.3.0"`.
- `effects.c2c.available`: `False`("not_provided") → `torch_reference` 가용성과 동일(D2D/Retention/ADC와 같은 패턴). 계산 모듈이 실제로 연결됐으므로 더 이상 "not_provided"가 아니다.
- `limits.max_n_reprogram`: 100 (신규).

## 알려진 커버리지 공백과 남은 제약

- 웹 입력 화면(apps/web)은 전혀 손대지 않았다. 사용자가 C2C를 켜려면 현재는 API를 직접 호출해야 한다.
- 측정 C2C 파서(실제 재기록 측정 데이터를 읽어 CV를 추정하는 기능)는 이번 범위가 아니다 — CV는 여전히 사용자가 수동으로 입력한 가정값이다.
- NeuroSim/PPA 연결은 이번 범위가 아니다(`effect_owners.c2c`는 `ctfm.simulation.math`로만 갱신, PPA 쪽은 그대로 미지원).
- `n_reprogram` 상한(100)과 실행 예산(2000) 조합에 따라 대규모 재기록 요청은 다른 축(arrays/pools/mappings/years)을 줄여야 할 수 있다 — 이는 기존 예산 정책의 자연스러운 결과이며 새로 추가한 제약은 아니다.
