# 구현 못한 것과 그 이유

2026-09-20 기준 · `구현못한이유.pdf`(2026-09-19)를 현재 상태로 다시 쓴 문서입니다.
구현된 항목은 [구현한 것](구현한것-2026-09-20.md), 실행 기록은
[구현·검증 상태](implementation-status.md)에 있습니다.

사유를 네 종류로 구분합니다. **어느 것이 "사용자 결정 대기"인지가 지난 문서와 가장 크게
달라진 부분입니다 — 대부분 아닙니다.**

| 표시 | 뜻 |
|---|---|
| `모델링` | 우리가 해야 하는 설계·구현 작업. 대기 사유 아님 |
| `자료` | 외부 자료(측정 파일, 형식 정의) 도착 전까지 불가 |
| `엔진` | upstream NeuroSim 자체의 제약 |
| `환경` | 이 호스트에서 실행 불가. 다른 호스트에서는 가능 |

## 지난 문서에서 바뀐 것 (먼저 읽어주세요)

지난 `구현못한이유.pdf`의 다음 두 서술은 **직접 측정으로 반증됐습니다.**

1. **"mnist_mlp_v1(784→128→10)은 preset 유무와 무관하게 현재 엔진으로 평가할 수 없다"**
   → 틀렸습니다. **subArray 256에서 완주합니다.** 이전 스윕이 이 형상에 대해 subArray 64와
   128만 시도했습니다. 재빌드가 고친 것이 아니라 배열 크기가 결정 요인이며, 스톡 바이너리도
   256에서 완주합니다.
2. **"출력 96 미만 레이어는 모두 crash"**
   → 틀렸습니다. `128×10`, `256×10`, `1024×10`, `256×64` 모두 subArray 64에서 완주합니다.
   이 잘못된 규칙이 코드의 `MIN_SAFE_OUT_FEATURES=96` 가드가 되어 **실제로 도는 형상을 거부**
   하고 있었습니다. 지금은 측정된 `(형상, subArray)` 쌍만 거부합니다.

따라서 **"엔진 crash 때문에 PPA 불가"는 더 이상 미구현 사유가 아닙니다.** 남은 사유는
아래와 같이 대부분 `모델링`입니다.

또한 지난 문서의 "A 차동 비용 — 아날로그 차감 모델 부재는 사용자 물리 판단 대기"는
결정 A5로 **합성 규칙이 확정**되어, 규칙 자체는 구현됐습니다. 남은 것은 규칙에 넣을 숫자입니다.

## 1. 전체 PPA 총계 `모델링`

**현상**: `area_m2`, `energy_j_per_inference`, `latency_s_per_inference`가 계속 `null`입니다.
엔진이 실행되어 숫자를 내놓아도 상태는 `partial`이고, 엔진 총계는 `engine_totals`에만 남습니다.

**이유**: 아래 네 블록에 비용 모델이 없습니다. 부분 비용은 공개하되 총계를 null로 두는 것은
[08 명세 §5](spec/08-hardware-baseline.md)가 요구하는 동작입니다.

### 1-1. `analog_subtraction_frontend` (차감 후 ADC) `모델링`
두 열 전류를 아날로그 영역에서 빼는 회로가 필요한데, unsigned current-mode MLSA는 같은 회로가
아닙니다. 부호 있는 sensing front end를 별도로 모델링해야 합니다. NeuroSim에 대응 블록이
없습니다.

### 1-2. `bipolar_range_conversion` (차감 후 ADC) `모델링`
부호 있는 열 전류를 변환기 입력 범위로 옮기는 것은 **회로이지 단위 변환이 아닙니다.**
현재는 "이상적 range scaling을 가정했고 그 비용은 누락"이라고 표시만 합니다.

### 1-3. `digital_subtraction` (개별 ADC 후 차감) `모델링`
디지털 차감과 그 뒤의 bit significance shift-add는 **구조적으로는 집계**되지만
(`circuit_inventory`) 면적·에너지 모델이 연결돼 있지 않습니다.

### 1-4. `per_block_engine_costs` (양쪽 공통) `엔진` + `모델링`
합성 규칙(`compose_differential_cost`)은 구현했습니다 — per-plane 블록은 두 plane 합산,
shared 블록은 1회, 지연은 `max(plane) + 공통 누산·차감`, 전체 2배 금지. **넣을 숫자가 없습니다.**

**구체적 이유 (2026-09-20 실제 엔진 출력 확인):** NeuroSim의 보고 단위가 합성 규칙이 요구하는
per-plane / shared 구분과 어긋납니다.

엔진이 주는 것:
- 면적: `ChipArea`, `Chip total CIM array`, `Total IC Area`, `Total ADC Area` — **4개 버킷**
- 지연·에너지: `ADC`, `Accumulation Circuits`, `Other Peripheries` — **3개 버킷**
  (레이어별로 `buffer`, `ic`는 따로 보고)

합성에 필요한 것과의 대응:

| 필요한 블록 | 구분 | 엔진에서 얻을 수 있나 |
|---|---|---|
| array | per-plane | 면적만 (`CIM array`). 지연·에너지는 다른 버킷에 섞임 |
| row_driver | per-plane | ✗ `Other Peripheries`에 포함 |
| column_multiplexer | per-plane | ✗ `Other Peripheries`에 포함 |
| input_buffer | shared | 레이어별 `buffer latency/energy`로 분리 가능 |
| interconnect | shared | `IC Area`, 레이어별 `ic latency/energy`로 분리 가능 |
| final_accumulator | shared | ✗ `Accumulation Circuits`에 포함 |
| bit_significance_shift_add | shared | ✗ `Accumulation Circuits`에 포함 |

문제의 핵심은 **`Other Peripheries`가 per-plane 블록(row driver, column mux)과 shared
블록(buffers, IC, pooling, activation)을 한 버킷에 섞고**, `Accumulation Circuits`가 subarray
레벨(per-plane)과 PE/Tile/Global 레벨(shared)을 섞는다는 점입니다. 이 출력만으로는
"per-plane은 두 번, shared는 한 번" 규칙을 적용할 수 없습니다.

**해결 경로** (택일 필요, 우리 작업):
- (a) NeuroSim 내부 객체에서 블록별 면적·지연·에너지를 직접 뽑도록 엔진에 계측 패치 추가
- (b) 블록별 비용을 별도 해석 모델로 산정하고 엔진 결과는 교차 검증에만 사용
- (c) 총계 포기하고 ADC/누산/기타 3버킷 수준의 조건부 비교만 제공

## 2. NeuroSim 배열 64·128에서의 mnist_mlp_v1 `엔진`

`784×128×10`은 subArray **64와 128에서 SIGSEGV**(CopyPEArray 내부)로 죽습니다. 256에서는
완주합니다. 최소 재현은 `[[257,1],[1,1]]`이며 3회 재실행 모두 재현됩니다.

crash는 fan_in에 단조롭지 않습니다: 257·260·320 죽고 **512는 살고** 784 죽습니다.
subArray에도 의존합니다(257은 32·64에서 죽고 128에서 삶). 일반 규칙을 주장하지 않습니다.

**결과**: 명세가 허용하는 배열 64/128/256 중 **256에서만** 이 모델의 PPA가 가능합니다.
64/128을 쓰려면 upstream 패치가 필요하며, 그 경우 최소 재현 케이스를 회귀 검사로 남깁니다.

---

## 3. 읽기 구간 성립 검사 `엔진`

`schedule_feasibility`는 항상 `not_performed`을 반환합니다 — **`feasible`로 위장하지
않습니다.**

**이유**: 10ns 읽기 가정과 비교할 subarray 단위 sensing 지연을 엔진 요약이 보고하지 않습니다.
엔진이 주는 `ADC readLatency`는 타일·cycle 전체에 걸친 합이라 단일 읽기 구간과 직접 비교할 수
없습니다. 비교 가능한 값을 얻으려면 1-4와 같은 계측 패치가 필요합니다.

---

## 4. C2C `자료`

파일 형식이 정해지지 않았습니다. 필요한 것은 **동일 소자 reset → 같은 기록 조건 → read 반복의
개별 전류와 조건**입니다. 평균·표본 std·CV 계산은 형식이 오면 바로 구현 가능합니다.

현재: 계약 `c2c: false` 고정, UI disabled, capabilities `not_provided`. 임의 수치를 넣지
않습니다.

---

## 5. 실측 A1 회귀 `자료`

원본 측정 파일이 제공되지 않았습니다. 테스트는 skip 상태로 존재하며 파일을 주면 그대로
돕니다(`CTFM_A1_FILE`).

인수 조건은 **행 번호 검증으로 이미 교체**했습니다(전환 행 j → 읽기 행 j-2). 개수 1024/1022는
파일별 provenance이므로 `CTFM_A1_EXPECTED_TRANSITIONS` / `_READ_STATES`를 지정했을 때만
단언합니다. 한 시트가 두 극성을 동시에 담을 수 없으므로 분석 방향은 `CTFM_A1_DIRECTIONS`로
지정합니다.

**작업 중 발견한 기존 결함 2건을 고쳤습니다**: `source_rows`를 분석기에 전달하지 않았고,
열 매핑을 `columns=`로 넘겨 분석기가 읽지 못했습니다. 실제 파일이 왔어도 그대로는 실행되지
않는 상태였습니다.

---

## 6. AIHWKit bit-serial 경로 실행 검증 `환경`

검증 스크립트는 v1.2 경로(8bit bit-serial + 두 plane + 두 순서, 39개 조합)로 교체했습니다.
**AIHWKit로는 실행하지 않았습니다.**

**이유**: AIHWKit은 Windows wheel이 없고(manylinux/macOS arm64만), 이 호스트에는 설치돼
있지 않습니다. 같은 코드를 `torch_reference`로 치환해 39/39 통과만 확인했습니다.
Linux 엔진 호스트(torch 2.12.0 + AIHWKit 1.1.0)에서 실행해야 합니다.

---

## 7. ADC off 상태의 PPA 비교 `설계상 제외`

미구현이 아니라 **의도적으로 지원하지 않습니다.** ADC off는 실물 ADC를 제거한 회로와 같지
않으므로 비용 비교에 쓰면 잘못된 결론이 나옵니다(08 §6). 정확도만 제공합니다.

---

## 8. 브라우저 UI 검증 `환경`

두 ADC 순서를 브라우저에서 실제로 선택해 결과까지 확인하는 headless 검증을 하지 않았습니다.
HTTP 계층과 계약은 테스트로 덮여 있고, 프론트는 타입 검사·단위 테스트·production build가
통과합니다. 전체 흐름 확인에는 MNIST 다운로드를 포함한 풀 스택 기동이 필요합니다.

## 의존 관계 요약

```
[자료 대기]  A1 원본 파일 ─→ 5. 실측 회귀 실행
             C2C 형식     ─→ 4. C2C parser + profile 계약

[우리 작업]  1-4 블록별 비용 확보 방식 선택 (a/b/c)
                 ├→ 1-1 아날로그 차감 front end 모델
                 ├→ 1-2 bipolar range 변환 모델
                 ├→ 1-3 digital subtraction 비용 연결
                 └→ 1. 전체 PPA 총계 공개 가능
             1-4 (a) 계측 패치 선택 시 ─→ 3. 읽기 구간 검사도 해결

[엔진]       2. subArray 64/128 crash ─→ upstream 패치 (256은 지금 동작)

[다른 호스트] 6. AIHWKit 실행, 8. 브라우저 검증
```

**가장 먼저 정할 것은 1-4의 (a)/(b)/(c)** 입니다. 나머지 비용 항목이 전부 여기에 걸려 있고,
(a)를 택하면 3번도 같이 해결됩니다.
