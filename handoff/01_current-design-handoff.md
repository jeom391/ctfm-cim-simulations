# CTFM-CIM 프로젝트 최신 설계 인수인계

작성일: 2026-09-17
상태: **현재 설계의 기준 문서. 아직 최종 개발 명세는 아님.**
목적: 새 채팅에서 측정 데이터, Device Profile, CIM 시뮬레이션 입력·출력 설계를 마무리하고 최종 MD 명세를 작성하기 위한 인수인계

## 1. 새 채팅에서 지켜야 할 진행 순서

1. 이 문서를 먼저 끝까지 읽는다.
2. 아래의 `확정`, `미확정`, `폐기` 구분을 유지한다.
3. 기존 문서와 충돌하면 이 문서의 최신 결정을 우선한다.
4. 바로 구현하지 않고, 미확정 항목을 사용자와 먼저 합의한다.
5. 합의가 끝나면 측정 데이터 분석과 CIM 시뮬레이션의 최종 개발 명세를 `docs/`에 작성한다.

완료 기준은 **입력 데이터, 계산 책임, Device Profile, 시뮬레이션 로직, 출력 결과, 화면 간 연결이 모호하지 않은 최종 명세 MD가 사용자 검토를 통과하는 것**이다.

## 2. 프로젝트 목적

물리·반도체 팀이 제작한 CTFM 소자의 특성을 AI CIM 환경에 반영하여 다음을 평가한다.

- 학습 완료 모델의 가중치를 실측 전도도 상태로 표현했을 때의 정확도 손실
- 소자 간 편차(D2D)와 재프로그램 편차(C2C)에 따른 추론 안정성
- 모델, ADC 정밀도, 배열 크기 등 조건별 정확도 비교
- NeuroSim 기반 면적·에너지·지연시간 등 하드웨어 성능 추정

핵심은 **소자 측정 자체를 대신하는 것**이 아니라, 확정된 소자 특성이 AI 정확도와 하드웨어 설계에 미치는 영향을 평가하는 것이다.

## 3. 웹 서비스 구조 — 확정

홈 화면에서 두 기능을 선택하며, 각 기능은 별도 페이지로 이동한다.

```text
홈
├─ 측정 데이터 분석
└─ CIM 시뮬레이션
```

### 3.1 측정 데이터 분석 페이지

측정 원본에서 필요한 계산을 수행하는 별도 도구다. CIM 시뮬레이션과 기능·입력·출력을 분리한다.

```text
분석 항목 선택
→ Excel 업로드
→ 계산 대상과 기준 입력
→ 결정적 계산
→ 표·그래프 확인
→ 소자팀 검토
→ 필요한 값만 Device Profile에 반영
```

원칙:

- AI API로 비교군, 이상값, 유효 상태를 판단하지 않는다.
- 연구자가 지정한 대상과 공식에 따라 같은 입력에서 같은 결과를 내는 계산만 수행한다.
- 계산 결과를 검토 없이 CIM 시뮬레이션에 자동 적용하지 않는다.
- 상세 계산 항목은 아직 최종 합의 전이다.

구현 후보:

- 평균·표준편차·상대 표준편차
- D2D 및 C2C 통계
- 문턱전압
- 메모리 윈도우
- Dynamic Range
- Retention 손실률
- 결과 표·그래프와 파일 출력

각 항목의 비교 대상, 제외 데이터, 계산법, 평가 시점은 소자팀이 지정해야 한다.

### 3.2 CIM 시뮬레이션 페이지

검토·확정된 Device Profile을 사용하여 AI 정확도와 하드웨어 성능을 평가한다.

```text
Device Profile 선택
→ 학습 완료 AI 모델 선택
→ 반복 실험 설정
→ ADC·배열 등 하드웨어 설정
→ AI 추론 및 NeuroSim 실행
→ 정확도·안정성·하드웨어 결과 비교
```

## 4. 역할 경계 — 확정

### 소자팀

- 사용할 전도도 상태를 확정한다.
- D2D 비교 대상과 유효 데이터를 선택한다.
- 동일 소자의 C2C 반복 측정 범위를 정의한다.
- D2D·C2C 대표 상대 표준편차를 계산한다.
- 측정·분석 기준이 필요한 항목의 기준을 정한다.

### 측정 데이터 분석 프로그램

- 정해진 형식의 데이터를 읽는다.
- 사용자가 명시한 대상과 공식으로 계산한다.
- 계산 결과를 표·그래프로 보여주고 내보낸다.
- 물리적 의미, 비교 대상, 제외 데이터는 스스로 판단하지 않는다.

### CIM 시뮬레이터

- 완성된 Device Profile을 입력받는다.
- 학습된 모델의 가중치를 전도도 상태에 매핑한다.
- D2D와 C2C를 적용해 반복 추론한다.
- 정확도 손실·안정성과 하드웨어 성능을 출력한다.
- 원본 측정곡선을 재분석하거나 소자 데이터를 재판정하지 않는다.

## 5. 소자팀에 요청할 CIM 입력 데이터 — 현재 합의

| 데이터 | 입력 방식 | 용도 |
|---|---|---|
| 소자 이름 | 직접 입력 | R1, R2 등 Device Profile 구분 |
| LTP/LTD 데이터: Program/Erase 펄스 Train에 따른 단계별 컨덕턴스 G | Excel 업로드 | 학습된 가중치를 실측 전도도 상태에 매핑 |
| Weight States | LTP/LTD Excel의 채택 상태 목록 사용 | 실제 사용할 전도도 상태 수 결정 |
| Gmin/Gmax | 직접 입력 | 가중치 매핑 범위 및 NeuroSim 저항 조건 설정 |
| D2D 값 | 직접 입력 | 가상 배열마다 서로 다른 소자 편차 적용 |
| C2C 값 | 직접 입력 | 같은 배열을 재프로그램할 때마다 발생하는 편차 적용 |
| 읽기 조건 VGS, VDS | 직접 입력 | 각 단계의 안정화된 G를 읽은 조건 기록 |
| 컨덕턴스 G 단위 | 화면에서 선택 | µS, mS 등 입력 단위 통일 |

LTP/LTD Excel의 최소 후보 열:

- `state_id`
- `direction` (`Program` 또는 `Erase`)
- `pulse_step`
- `conductance_g`
- 최종 상태만 담지 않고 후보 전체를 받을 경우 `selected` 여부

정확한 열 이름과 필수 여부는 새 채팅에서 최종 확정해야 한다.

## 6. D2D·C2C 정의와 적용 — 확정

### 입력값

- 문턱전압 편차가 아니라, 가중치 상태로 사용하는 컨덕턴스 G의 편차를 사용한다.
- 현재 UI는 각 Device Profile에 공통 적용할 D2D 대표값 1개와 C2C 대표값 1개를 직접 입력한다.
- 값은 상대 표준편차 `sigma_G / mean_G`의 소수 형식으로 통일하는 안이다.
- 예: `0.08`은 평균 전도도 대비 표준편차 8%를 의미한다.
- 상태별 편차 입력은 정밀 확장 후보이며 현재 기본안이 아니다.

### 시뮬레이션

- `m`: 서로 다른 D2D 특성을 가진 가상 배열 수
- `n`: 각 가상 배열을 같은 목표 상태로 다시 프로그램하는 횟수
- 배열 하나를 생성할 때 D2D를 한 번 뽑고 그 배열에서 고정한다.
- 각 재프로그램 회차마다 C2C를 새로 뽑는다.
- 총 `m × n`개의 추론 결과를 이용해 정확도 분포와 안정성을 계산한다.

주의:

- 독립적인 C2C만 적용하면 cycle 번호에 따른 **무작위 산포**를 평가한다.
- 반복할수록 성능이 낮아지는 누적 열화를 주장하려면 별도의 endurance 데이터가 필요하다.

## 7. AI 모델과 전도도 매핑 — 확정

현재 기본 범위는 **학습 완료된 디지털 모델의 사후 매핑 및 추론 평가**다.

```text
학습 완료 모델
→ 부호 있는 가중치를 차동쌍 G+/G-로 표현
→ 각 값을 측정된 유한 전도도 상태로 매핑
→ D2D·C2C 적용
→ 동일 테스트셋으로 추론
→ 디지털 기준과 정확도 비교
```

- 소자 특성에 맞춘 hardware-aware 재학습은 AIHWKit에서 가능하지만 현재 기본 범위가 아니다.
- 재학습을 추가할 경우 `매핑 직후 손실`과 `재학습 후 회복`을 분리해 별도 실험으로 정의해야 한다.
- 사용자가 모든 신경망 가중치나 가상 소자를 직접 생성하지 않는다. 모델 변환·타일 구성·반복 실행은 프로그램이 수행한다.

## 8. AIHWKit·NeuroSim 역할 — 현재 설계

### AIHWKit

- PyTorch 모델의 아날로그 추론 구성
- 차동쌍 표현, 타일링, ADC/DAC 등 아날로그 연산 설정
- D2D·C2C를 반영한 정확도 실험

주의: AIHWKit의 기본 converter는 Gmin~Gmax의 연속 매핑 또는 목록 사이 보간을 사용한다. 실측한 불규칙 유한 상태만 허용하려면 별도의 상태 선택 로직 또는 `BaseConductanceConverter` 확장이 필요하다. D2D·C2C의 실측 정의에 맞춘 사용자 정의 잡음 처리도 필요할 수 있다.

### NeuroSim

- 배열·ADC·주변회로 조건에 따른 면적, 에너지, 지연시간 등 PPA 추정
- 일반적인 Python 패키지처럼 단순 import하는 도구로 가정하지 않는다.
- Python 실행기가 NeuroSim wrapper/C++ 엔진을 호출하고 결과를 공통 형식으로 파싱하는 구조를 검토한다.
- 회로 조건의 상당 부분은 실측값이 아니라 가정값이므로 결과에 실측/가정 구분을 남긴다.

## 9. 시뮬레이션 실행 설정 — 소자팀 제공값과 분리

다음 값은 소자 측정값이 아니라 실험·하드웨어 연구를 위해 사용자가 설정한다.

- 비교할 Device Profile
- AI 모델(MLP, CNN 등)
- 가상 배열 수 `m`
- 재프로그램 횟수 `n`
- D2D·C2C 분포 가정(현재 Gaussian 후보)
- ADC 정밀도
- 배열 크기
- NeuroSim 기술 노드와 주변회로 조건
- 데이터셋, 체크포인트, seed 정책

## 10. 결과 출력 — 현재 방향

### AI 정확도·안정성

- 디지털 기준 정확도
- 소자 적용 후 평균 정확도
- 정확도 손실(%p)
- 반복 결과 표준편차·분위수·분포
- Device Profile별 비교
- 모델별 비교
- ADC 정밀도별 정확도

### 하드웨어 추정

- 면적
- 에너지
- 지연시간
- 필요하면 throughput, TOPS/W 등 NeuroSim 제공값

UI 목업의 수치는 모두 설명용 임의값이며 연구 결과가 아니다.

## 11. 현재 범위에서 분리된 항목

- 문턱전압과 메모리 윈도우는 CIM 정확도 계산에 직접 넣지 않는다.
- EPSC/IPSC 및 PPF/PPD는 정적 MNIST MLP/CNN 추론과 분리한다.
- Retention은 상태별 시간 데이터와 평가 정의가 합의될 때 선택 기능으로 추가한다.
- 누적 endurance 열화는 일반 C2C와 분리한다.
- 측정 원자료를 AI API로 해석하거나 비교군·이상값을 선택하지 않는다.

위 값의 계산이 필요하면 측정 데이터 분석 페이지에서 별도 기능으로 정의한다.

## 12. 다음 채팅에서 최종 합의할 사항

### 측정 데이터 분석

1. 실제 구현할 계산 항목 목록
2. 항목별 입력 Excel 스키마
3. 연구자가 직접 지정해야 하는 기준과 UI 입력 방식
4. 계산식과 단위
5. 표·그래프·다운로드 결과
6. Device Profile 반영 전 검토·확정 절차

### Device Profile

1. LTP/LTD Excel이 모든 펄스 단계인지 최종 채택 상태만인지
2. `selected` 상태를 누가·어떤 기준으로 결정하는지
3. Gmin/Gmax 직접 입력과 Excel 상태 목록의 일치 검증 방식
4. D2D·C2C 대표 상대 표준편차 산출 기준
5. D2D·C2C 분포를 Gaussian으로 고정할지 선택 가능하게 할지
6. 프로필 저장 형식, 버전, 필수값, 검증 오류 메시지

### CIM 시뮬레이션

1. 제공할 AI 모델과 체크포인트
2. 가중치→유한 전도도 상태 매핑 규칙
3. 차동쌍의 정확한 상태 선택 규칙
4. D2D·C2C 적용 순서와 경계값 처리
5. `m`, `n`, seed 기본값
6. ADC·배열 크기 등 추천 기본값
7. AIHWKit과 NeuroSim 결과를 합치는 공통 결과 스키마
8. 웹 프론트와 실행 백엔드의 인터페이스

## 16. 새 채팅 시작 프롬프트

아래 문장을 새 채팅의 첫 요청으로 사용할 수 있다.

> 저장소의 `handoff/01_current-design-handoff.md`를 먼저 끝까지 읽고, 문서가 가리키는 기술 참고 자료만 필요한 범위에서 확인해줘. 기존 문서와 충돌하면 인수인계 문서의 최신 결정을 우선해줘. 바로 구현하거나 기존 문서를 수정하지 말고, 먼저 측정 데이터 분석 페이지, Device Profile, CIM 시뮬레이션 입력·출력에서 아직 결정되지 않은 사항을 이해하기 쉽게 정리해줘. 이후 나와 하나씩 합의하여 최종 개발 설계 MD를 작성하는 것이 이번 채팅의 목적이야.
