## 2. 확정 범위와 권장 내부 설정

### 사용자가 확정한 범위

- 이번 제품은 **측정 분석 및 MNIST 정확도 비교**에 집중한다.
- 배열은 **64×64로 고정**한다. 새 실행 화면에서 128/256 선택을 제거한다.
- **전체 PPA는 후속 연구로 둔다.** 혼동 방지를 위해 이번 기본 UI에서는 부분 비용도 포함해 PPA 옵션·결과 카드·preset 입력을 제거하고 정상 실행에서 NeuroSim 비용 평가를 호출하지 않는다.
- 기존 PPA 코드·엔진 패치·과거 결과는 보존한다. 과거 비용 수치를 정확도 결과로 재해석하거나 지우지 않는다.
- ADC 비트 수는 사용자 비교 변수로 유지한다. D2D·C2C·Retention 정확도 영향도 유지한다.
- 측정은 파일 업로드 중심으로, 고정된 약속·자동 판별 가능한 설정은 입력칸 대신 조건 요약으로 표시한다.
- 측정 분석과 시뮬레이터의 프로필 구성은 분리한다. 단일 재측정이 기존 연결을 자동 교체하면 안 된다.

### 개발에 사용할 권장안

- ADC는 OFF 또는 3~8 bit, 기본 5 bit. 순서는 `adc_then_subtract`로 고정: 두 전도도 경로를 각각 ADC 처리한 뒤 디지털 차감한다. 고정 순서를 한 줄로 표시하고 선택창은 숨긴다.
- 입력 인코딩 8 bit 및 기존 검증된 MNIST 모델·체크포인트 정책을 유지한다. ADC OFF를 FP32 기준과 동일하다고 표기하지 않는다.
- 한 묶음의 공통 조건은 ADC 설정, 반복 횟수, 비이상성 on/off, Retention 평가 연수이다. 프로필마다 이 값을 중복 입력하지 않는다.
- 반복 횟수는 의미를 나눠 표시한다: **소자 배열 반복(D2D)** / **같은 배열 재기록 반복(C2C)**. 둘을 한 칸으로 합치지 않는다. 해당 효과 OFF 시 관련 입력을 숨긴다. 범위·상한은 기존 검증기를 유지한다.
- 풀/매핑은 기존 계산 방식을 유지하되 기본 화면에서는 프로젝트 기본값으로 시작하고 '비교 옵션'에 둔다. 여러 풀/매핑을 실행할 때 후보별 결과를 구분한다. 임의로 새 물리 모델이나 수치를 추가하지 않는다.
- 기본 시뮬레이션은 미확인 비이상성을 강제 적용하지 않는다. 필요한 자료가 없는 효과는 '자료 없음/확인 필요'로 표시하고, 끄면 매핑+ADC 실험을 실행할 수 있어야 한다. 누락 값을 0% 실측값으로 저장하지 않는다.

### 서버 정책과 과거 결과

신규 실행 경로는 서버에서도 64 및 고정 ADC 순서를 검증한다. 프론트만 숨겨서 다른 값이 그대로 계산되면 안 된다. 이전 계약으로 128/256·PPA를 요청한 클라이언트에는 명확한 범위 제한 오류 또는 별도 legacy 실행 경로를 제공하며, 값을 몰래 64로 바꾸지 않는다. 과거 기록은 당시 설정을 그대로 읽을 수 있게 한다. 새 결과의 PPA 상태는 '평가하지 않음'이며 0원가/실패로 표시하지 않는다.

## 4. 측정 분석: 파일만 올리는 기본 흐름

### 기본 화면

1. CSV/XLSX 여러 파일을 한 번에 올린다. 파일명·시트·헤더·내용으로 분석 유형/조건 ID/방향을 인식한다.
2. 파일 목록과 인식한 종류·조건을 보여주고 분석한다. 확실한 경우 불필요한 드롭다운/확인 체크박스는 요구하지 않는다.
3. 모호한 방향·단위·자료 짝만 간단한 선택으로 해결한다. 조건 ID(A1 등)는 물리적 소자 ID를 뜻하지 않는다.
4. 결과는 요약·그래프 우선, 원시 JSON은 개발 진단/다운로드로 옮긴다. 상태 목록은 페이지 나누기 유지.
5. 측정 결과를 보관해도 시뮬레이터 프로필을 자동 발행·자동 변경하지 않는다. 분석 자체는 각 유형별로 독립 수행 가능하다.

### 조건은 입력 대신 명시하되, 자료와 충돌하면 알린다

| 항목 | 기본 처리 | 예외 |
|---|---|---|
| LTP/LTD | 쓰기 폭 1 ms, 읽기 구간 1 ms, 합의한 Read VGS 0 V·VDS 0.1 V를 프로젝트 조건으로 표시. 절대 읽기 전류를 G=I/0.1로 환산 | 파일에 조건 근거가 없으면 '프로젝트 가정'과 '파일에서 확인'을 구분. 충돌 시 자동 적용 금지 |
| LTP/LTD 쌍 | 동일 조건·측정 묶음의 두 방향을 함께 분석; 둘 중 하나만 있으면 임시 보관 | 쌍 후보가 여러 개면 해당 쌍만 사용자가 선택. 서로 다른 측정의 파일을 이름만으로 몰래 합치지 않음 |
| 추출 시점 | 기존 검증된 전환 전 j-2 추출 규칙 유지 | 시작 시각은 모든 파일을 무조건 6초로 자르지 않는다. 파형/메타데이터로 인식하고 1초 등 차이는 요약에 기록. 근거가 모호하면 최소 확인을 요청 |
| 단위·열 | 헤더/장비 형식에서 자동 인식 | A/µA 및 전류·전압 열을 임의 추측해 실행하지 않음. 충돌만 고급 확인으로 노출 |
| IV/CCM | Iref=1 µA, 기존 선형 보간, MW=abs(Vth,P−Vth,E) | 로그 보간으로 몰래 변경하지 않음. 여러 스윕 블록은 각각 분석·구분, 임의 첫 블록 채택 금지 |
| D2D | 기존 식 유지 | 동일 조건의 서로 다른 물리 소자라는 근거가 없으면 비교 대상을 최소한으로 확인. A1/A2를 자동 D2D 쌍으로 만들지 않음 |
| Retention | 기존 10초 이후 적합·로그 시간 식 유지 | 읽기 VGS는 Retention 자료별 조건을 따른다. LTP의 0 V를 전체 파일에 일괄 덮어쓰지 않음. 제외 자료·외삽 표시 유지 |
| C2C | Origin_data의 cycle·Program·Erase 전류, 기존 추세 제거 분석 | 최신 파일 조건 미확정. 5 V·1 ms로 자동 확정하지 않음. A2/A4의 결측·부호 문제를 임의 삭제/보간/절댓값 처리하지 않음 |

고급 정보는 기본 접힘으로 둔다. 실제 선택지가 하나뿐인 열/모델/단위는 읽기 전용 정보로 바꾼다. 필요한 데이터 확인까지 숨겨 잘못된 결과를 만드는 방식으로 간소화하지 않는다.

## 5. 시뮬레이터: 사용자가 만드는 비교 묶음

### 화면 흐름

1. **새 시뮬레이션** → 빈 비교 묶음을 만든다.
2. **+ 디바이스 프로필 추가** → 프로필 카드 추가. 카드에서 표시 이름과 사용할 LTP/LTD 분석 결과 한 쌍을 선택한다. 필요 시 D2D/C2C/Retention 분석 결과를 개별 연결한다. 기존 프로필을 선택·복제하는 것도 허용한다.
3. 프로필마다 상태 수·전도도 범위·원본 파일·분석 revision·선택된 효과 자료·적용 가능 여부를 간단히 표시한다. CV 등은 선택한 분석에서 읽고 반복 입력하지 않는다.
4. 카드 아래에 **공통 실행 조건**을 한 번만 설정한다. ADC 5 bit 등을 바꾸면 묶음 전체에 적용한다.
5. **비교 실행** → 동일 체크포인트·MNIST 평가 표본·공통 seed 정책을 사용한다. baseline을 공유할 수 있으나 프로필별 수치를 복사하지 않는다.
6. 결과에서 각 프로필의 디지털 기준/매핑 후/효과 반영 정확도와 감소량을 나란히 본다. 실패하거나 자료 없는 프로필은 이유를 보여주고 다른 프로필 결과를 보존한다.
7. **결과 저장** → 이름을 입력하고 저장한 결과 목록에 추가한다.

### 단일 재측정과 연결 규칙

- 원본 업로드 → 분석 revision → 프로필 revision → 실험 스냅샷을 분리하고, 참조는 불변 ID/해시로 고정한다.
- 예: A3 C2C만 재측정하면 새 C2C 분석이 추가될 뿐 기존 A3 프로필과 저장한 실험은 바뀌지 않는다.
- 사용자가 새 묶음의 A3 카드에서 'C2C 자료 교체'를 선택하면 새 프로필 revision을 생성한다. LTP/LTD·D2D·Retention 연결은 유지하고 변경 내역을 보여준다.
- 재측정 LTP만 추가됐다고 과거 LTD와 자동 결합하지 않는다. 기존 LTD를 재사용하려면 사용자가 명시적으로 쌍을 선택한다.
- 실행 시작 시 모든 참조와 공통 설정을 스냅샷으로 고정한다. 실행 중 자료 교체는 그 실행에 영향을 주지 않는다.
- 기본 경로는 분석 결과 선택이다. 수동 CV 가정 등 기존 전문가 경로는 필요하면 고급 메뉴에 유지하고 실측값과 명확히 구분한다.
- 조건이 다른 C2C를 다른 프로필 전체에 적용하려면 기존의 교차 조건 적용 가정 기록을 유지한다. 파일이 존재한다는 이유로 승인을 자동 생성하지 않는다.

### 저장 방식 권장안

**페이지를 닫는 즉시 삭제하지 않고, 임시 보관과 정식 저장을 구분한다.** 긴 계산 중 새로고침·탭 종료·통신 끊김으로 결과가 사라지는 것을 피하기 위해서다.

- 묶음 상태: 작성 중 → 실행 중 → 임시 결과 → 저장됨. 실패/취소도 상태를 보존한다.
- 작성 중 설정과 실행 ID를 서버에 임시 저장하고 새로고침 후 복구한다. 히스토리 기본 목록에는 이름 붙여 저장한 결과만 노출하고, 별도 '임시 작업'에서 재개/버리기를 제공한다.
- 저장은 계산 재실행이 아니라 기존 결과에 이름을 붙여 확정하는 작업이다. 중복 클릭으로 중복 기록을 만들지 않는다.
- '버리기'는 해당 임시 묶음과 전용 산출물만 정리한다. 공유 업로드·분석·다른 실험·저장된 프로필을 삭제하지 않는다. 실행 중이면 취소 완료 후 정리한다.
- 이번 구현에서는 임시 작업 자동 만료는 두지 않는다. 자동 삭제 정책은 별도 도입한다. 사용자가 직접 버릴 수 있으면 충분하다.
- 저장한 기록을 다시 돌릴 때는 복제해 새 묶음을 만든다. 기존 결과를 덮어쓰지 않는다.

- 계약: `packages/contracts/models.py`와 OpenAPI/Schema 생성기. 생성된 TS 타입은 수동 수정하지 않고 재생성한다.
- 기존 experiment/profile 모델을 우선 재사용한다. 묶음 ID, 저장 상태/이름, 선택 profile revision 목록, 공통 설정, 후보별 작업/결과 참조를 추가하되 기존 기록 마이그레이션과 읽기를 검증한다.
- UI에서 계산식을 복제하지 않는다. 자동 판별·고정 조건도 서버가 검증하고 resolved config에 기록한다.
- 결과·내보내기에는 파일 해시, 분석/프로필 revision, 모델/checkpoint/데이터셋 식별자, 실제 ADC/64 설정, 반복/seed, 적용 가정을 보존한다.

## 7. 필수 검증 및 인수 기준

1. 새 실행 화면에 PPA/NeuroSim preset/128·256/ADC 순서 선택이 없고, 서버에서도 정책을 지킨다. 정상 정확도 실행 중 NeuroSim 미호출을 검증한다.
2. 최신 A1~A5 LTP/LTD 열 파일을 실제 업로드해 다섯 쌍으로 구분한다. 여러 파일 동시 선택, 파일 순서 변경, 한 방향 누락, 중복 쌍을 확인한다. 후보 상태 개수는 데이터에서 계산하며 512/1020으로 하드코딩하지 않는다.
3. 시트·헤더 앞 remarks/보조표를 처리하고 단위 변환 및 기존 j-2 규칙이 유지된다. 인식한 실제 시작 시각을 표시한다.
4. IV/Retention 최신 파일 읽기 회귀 및 D2D 물리 소자 선택 검증. C2C A2/A4는 잘못된 값으로 조용히 성공하지 않고 행/이유를 보여준다.
5. 한 묶음에 두 개 이상 프로필을 추가하여 ADC·반복 조건이 공통 적용되고 결과가 후보별로 분리된다. 같은 체크포인트/표본 비교를 확인한다.
6. C2C만 교체한 새 revision을 만들어 이전 프로필·저장 실험이 바뀌지 않는지 확인한다. C2C OFF 상태에서는 미확인 C2C 자료가 실행을 막지 않는다.
7. 임시 실행 새로고침 복구, 이름 저장, 목록 다시 열기, 복제 실행, 버리기를 확인한다. 버리기 후 공유 측정 자료가 남아야 한다.
8. 기존 계약 읽기/과거 결과 보존, OpenAPI/schema drift, TS/build, 관련 Python·웹 검사 수행. 측정식 수정 없이 나온 결과가 변하면 원인을 보고한다.
9. **실제 브라우저에서 파일 입력 → 분석 → 새 묶음 → 두 프로필 추가 → 실행 → 이름 저장 → 재열기**를 검증한다. API-only 검증을 전체 UI 검증이라고 기록하지 않는다.

최종 보고는 `local_report/18_REPORT_scope-ui-refresh.md`에 구현 커밋, 수정 목록, 검사 명령/종료 코드, 브라우저 확인 범위, 자료별 제외 이유, 남은 연구 확인을 남긴다. 팀 공유용 요약은 `docs/`에도 커밋한다. 소자팀의 C2C 답변을 기다리느라 UI·64 고정·PPA 제외 구현 전체를 멈추지 않는다.

## 8. 발표에서 설명할 범위

“측정한 전도도 상태와 비이상성이 MNIST 정확도에 미치는 영향을 비교한다. 배열은 현재 검증한 64×64로 통일하고 ADC 분해능을 비교 변수로 둔다. 전체 가속기 PPA는 추가적인 회로 가정과 검증이 필요하여 이번 평가 범위에서 제외한다.”

64가 NeuroSim의 유일한 지원 크기이거나 물리적 최적 크기라고 주장하지 않는다. C2C 추세 제거 잔차를 순수한 독립 잡음으로 확정하거나, 원자료를 공유했다는 이유로 미확인 측정 조건이 확인됐다고 주장하지 않는다.
